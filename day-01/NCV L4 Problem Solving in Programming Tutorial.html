Part 2 of 6 Understand

🧩 Break it down: the IPO chart

Keyboards closed. First find out what the problem actually asks.

The requirement

Write a program that reads the price of an item and the quantity bought. Work out the total. If the total is over R500 give 10% discount. Add 15% VAT and display the amount to pay.
Explain it like I'm 6A recipe card has ingredients (Input), a method (Processing) and the dish (Output). An IPO chart is the recipe card for your program.
Detective trick: the nouns are usually Input or Output. The verbs (work out, give, add) are usually Processing.

Build the IPO chart

Spot the hidden decision: "if the total is over R500" is a choice (an IF). The number 500 is a boundary. Remember it for Part 5!
Part 3 of 6 Plan

📝 Plan the algorithm

An algorithm is a list of steps in the right order. Order matters: VAT must be added after the discount.

Pseudocode

Pseudocode is plain-English code. It is not a real language, so any programmer can read it.

Explain it like I'm 6Getting dressed: socks go on before shoes. Swap the order and the result is silly. Programs are the same.
Sequence (steps in order) + Selection (IF) are the building blocks you use here.

Part 4 of 6 Dry run

🔍 Trace table: be the computer

Before you run code, run it on paper. A trace table shows what each variable holds after every step.

The algorithm

1INPUT price, quantity
2total = price * quantity
3IF total > 500 THEN
4 total = total * 0.90
5END IF
6total = total * 1.15
7DISPLAY total
Explain it like I'm 6A trace table is a scoreboard. After every move you write down the new score, so you never lose track.

Tip: multiplying by 0.90 takes 10% off. Multiplying by 1.15 adds 15%.

Fill in the totals

Notice: with R400 the IF was false, so line 4 was skipped and total didn't change. Tracing both paths is how you prove a decision works.
Part 5 of 6 Test

🐞 Find the bugs, design the tests

This program runs without errors but a learner says it gives the wrong amount. That is a logic error.

Bug hunt: click the faulty lines

Remember the rule: over R500 gets 10% off. There are 2 faulty lines.

Line 4: >= includes exactly 500, but the rule says over 500, so it must be >. Line 5: * 0.10 keeps only 10% of the total; * 0.90 takes 10% off.

Test data

Explain it like I'm 6Testing a bridge: you don't only drive a bicycle over it. You try a truck, and you check the edge too!
Choose test data from 3 groups: Normal (typical values), Boundary (right on the edge, like 500) and Invalid (wrong values, like a negative price).
